# 로봇·자율주행 SW QA 버그 리포트 템플릿

Nav2/ROS2 주행 시험에서 나온 결함을 **다른 사람이 그대로 재현할 수 있는 형태**로 남기기 위한 양식입니다.
아래 1번 양식을 복사해 채우고, 2번 작성 기준과 3번 예시를 참고합니다.

- 대상: 자율주행 주행 스택(Nav2), ROS2 노드, 센서·토픽, 라벨링/데이터 파이프라인
- 원칙: 로그는 요약하지 않고 원문을 붙이고, 수치는 측정값과 기준값을 함께 적습니다.

## 2. 작성 기준

### 이슈 제목
`[모듈] 현상 + 재현 조건` 순서로 50자 이내. 검색으로 찾을 수 있게 증상 키워드를 넣고, "동작 안 됨"처럼 모호한 표현은 쓰지 않습니다.

### 심각도 (Severity) — 결함이 주는 영향 기준
| 등급 | 기준 |
|:---:|:---|
| **S1 치명** | 충돌·안전 사고·데이터 손실 |
| **S2 중대** | 주요 기능 수행 불가 |
| **S3 보통** | 우회 경로로 기능 가능 |
| **S4 경미** | 표시·문구 수준 |

### 우선순위 (Priority) — 일정·현장 영향 기준
심각도와 분리해서 판단합니다. 같은 S2라도 현장 적용 일정에 따라 P1이 될 수 있습니다.

| 등급 | 기준 |
|:---:|:---|
| **P1** | 즉시 수정 (현장 적용 전 필수) |
| **P2** | 릴리스 전 수정 |
| **P3** | 다음 릴리스 |

### 테스트 환경
OS·ROS 버전·시뮬레이터·로봇 모델·파라미터 파일(커밋 해시)까지 적습니다. 재현의 절반이 이 항목입니다.

### 관련 TC ID
시트의 TC ID와 시험 회차·재현율을 함께 적어 추적 가능하게 합니다. (예: `NAV-004 (2회차, 3/3 실패)`)

### 사전 조건
지도·초기 위치·파라미터·하드웨어 상태를 적습니다. 시험자가 그대로 따라 만들 수 있어야 합니다.

### 재현 스텝
명령어 단위로 5단계 이내. 누구나 같은 결과가 나오도록 실행 명령과 입력값(좌표, 파라미터)을 그대로 적습니다.

### 기대 결과
요구사항·파라미터 근거와 측정 기준값을 함께 적어 "무엇이 맞는 동작인지"를 남깁니다.

### 실제 결과
관측값·로그 원문·재현 횟수를 적습니다. 로그는 요약하지 말고 그대로 붙여 넣습니다.

### 첨부 자료
rosbag2 경로(파일명 포함), 콘솔 로그 파일, 스크린샷·영상, 사용한 파라미터 파일을 함께 올립니다. **첨부만으로 재현 가능한 상태**가 목표입니다.

### 상태
Open → In Progress → Verify → Closed 순으로만 변경하고, 담당자·수정 커밋·재검증 결과를 같은 스레드에 남깁니다.

### 등록 전 체크리스트
- [ ] 제목만 보고 모듈과 현상을 알 수 있는가
- [ ] 사전 조건대로 환경을 만들 수 있는가 (파라미터·맵·좌표 명시)
- [ ] 기대 결과에 판정 기준값(수치)이 있는가
- [ ] 실제 결과에 로그 원문과 재현 횟수가 있는가
- [ ] bag·로그·화면 첨부로 재현이 가능한가
- [ ] 관련 TC ID와 시험 회차가 연결되어 있는가

## 3. 작성 예시 (NAV-004 FAIL 기준)

### [Nav2 Planner] inflation 기본값에서 폭 0.40 m 통로 경로 생성 실패 (NAV-004)

- **심각도**: S2 — 충돌은 없으나 해당 폭 이하 구간 자율주행이 불가해 경로를 이탈해야 함
- **우선순위**: P1 — 물류 현장 통로 폭 0.5 m 이하 구간이 다수여서 우회가 어려움
- **관련 TC ID**: NAV-004 (2회차, 3/3 실패 / inflation 0.25로 낮춘 비교 회차는 통과)
- **등록일 / 담당**: 2026-11-17 / @planner-owner

#### 테스트 환경
- Ubuntu 22.04.4 / ROS2 Humble (2024-05 패치) / Gazebo Classic 11.10 / TurtleBot3 Waffle Pi
- `nav2_params.yaml` (commit a1b2c3d): `robot_radius: 0.22`, `inflation_radius: 0.55`, `cost_scaling_factor: 3.0`

#### 사전 조건
- 통로 폭 0.40 m로 수정한 world, `map_040.yaml`, AMCL (0, 0) 수렴 완료, goal (2.5, 0.0)

#### 재현 스텝
1. `ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py` (통로 0.40 m world)
2. `ros2 launch nav2_bringup navigation2.launch.py map:=map_040.yaml`
3. RViz `2D Pose Estimate` (0, 0) → `2D Goal Pose` (2.5, 0.0)
4. `/plan`과 planner_server 콘솔 로그 확인

#### 기대 결과
- 폭 0.40 m 통로(로봇 폭 0.281 m + 여유 0.119 m)에 대해 유효 경로가 생성되고, `goal_xy_tolerance` 0.25 m 내 도착(`SUCCEEDED`), 벽 접촉 0회

#### 실제 결과
- 3회 모두 `ABORTED`
- planner_server 로그 원문:
  - `"Failed to create plan with tolerance 0.50."`
  - `"Planning algorithm GridBased failed to generate a valid path to (2.50, 0.00)"`
- RViz costmap에서 통로 전체가 inflated 영역. 통로 0.6 m 앞 정지 후 제자리 회전 3회, 최종 오차 2.12 m

#### 첨부 자료
- rosbag2: `/ros2_ws/bags/nav_issue01_20261117` (`nav_issue01_0.db3`, 118 s, `/cmd_vel`·`/scan`·`/plan`·`/local_costmap/costmap`)
- 로그: `logs/planner_server_20261117.log`
- 스크린샷: `nav004_costmap.png`, `nav004_rviz.png`
- 파라미터: `nav2_params.yaml`

#### 상태
- Open (2026-11-17 등록, 담당 @planner-owner, 수정 커밋·재검증 대기)
